## 1. Итог

Реализована законченная Python-программа для локальной обработки продаж:

```bash
python -m arqenode_dataflow \
  --input examples/sales.xlsx \
  --output output/
```

Она читает CSV/XLSX, проверяет фиксированную схему, очищает данные, считает
выручку через `Decimal`, формирует пять листов `report.xlsx`, экспортирует
`cleaned.csv`, показывает итоги в CLI и возвращает корректные коды завершения.

Исходные файлы не изменяются. Существующие результаты по умолчанию не
перезаписываются: для этого требуется явный `--force`.

## 3. Архитектура и принятые решения

Поток обработки:

```text
CLI
 └─ reader.read_input()
     └─ validator.validate_table()
         └─ processor.build_summary()
             └─ reporter.write_outputs()
```

- **reader** не валидирует бизнес-данные, а только безопасно читает таблицу,
  нормализует заголовки и сохраняет номера исходных строк.
- **validator** не знает про Excel: он собирает `SaleRecord` и `RejectedRow`.
- **processor** не зависит от CLI и файловой системы, агрегирует записи.
- **reporter** отвечает только за представление, защиту от формул и запись.
- **CLI** переводит исключения в понятные сообщения и коды завершения.

Обоснование изменений относительно рекомендуемой структуры: добавлен
`errors.py` для единого типа пользовательских ошибок. Отдельный слой абстракций,
БД, веб-сервер и конфигурационные файлы не добавлялись.

### Денежные расчёты

- Используется `decimal.Decimal`.
- `unit_price` округляется до двух знаков `ROUND_HALF_UP`.
- `revenue = quantity * unit_price`, затем результат также округляется до
  копеек `ROUND_HALF_UP`.
- Итоги складываются из округлённых выручек строк, сумма также квантуется.
- Причина: воспроизводимость и отсутствие ошибок двоичной плавающей точки в
  расчётах.

### Дубликаты

- Ключ — все поля записи после нормализации и округления цены:
  `order_id`, дата, товар, количество, цена, категория.
- Одинаковый `order_id` с разными товарами/количествами не считается
  дубликатом.
- При совпадении сохраняется первое вхождение, последующие попадают в
  «Ошибки» отдельным видом отклонения.
- В сводке дубликаты учитываются отдельно от прочих ошибок.

### Безопасность

- CSV-значения, начинающиеся с опасных символов, получают префикс `'`.
- В XLSX все пользовательские строки принудительно записываются с типом
  `s`, а не формулой.
- Запрещены недопустимые XML-символы; слишком длинный текст Excel обрезается с
  явной пометкой.
- Выходные файлы пишутся через временный файл в целевом каталоге и
  `os.replace`.
- Результат не может совпасть с исходным файлом даже при `--force`.
- Внешние сервисы, база данных, сеть и секреты не используются.

## 8. Найденные и исправленные проблемы

1. **XLSX с данными в лишнем столбце.** `openpyxl` возвращал строку заголовка
   шириной по максимальному столбцу, из-за чего лишнее значение попадало в
   «пустой» седьмой столбец и не отклонялось. Исправлено: пустые хвостовые
   заголовки обрезаются, значения в безымянных столбцах и ячейки за пределами
   заголовка отклоняются с причиной.
2. **Номер строки при многострочном CSV-поле.** `csv.reader.line_num` после
   чтения указывал на последнюю физическую строку поля. Исправлено: для отчёта
   сохраняется начальная физическая строка записи.
3. **Проверка конечности цены.** В промежуточной версии условие проверки
   `Decimal` было избыточным и запутанным. Заменено на явную проверку
   `price.is_finite()`.
4. **Лист «Ошибки» и количества.** В промежуточной версии значение количества
   ошибочно пыталось интерпретироваться как денежное. Исправлено: исходные
   значения всех полей сохраняются как текст без «исправлений».
5. **Порядок и вид сводки.** После визуальной проверки выровнен номер места в
   топ-10, увеличены ширины служебных столбцов, график перенесён под таблицу
   месяцев, чтобы он не обрезался при просмотре.
6. **Формульная защита.** Все текстовые поля, включая исходные значения ошибок
   и названия товаров, проверены на запись как текст. Тест подтверждает
   отсутствие формульных ячеек в готовом XLSX.
7. **Совместимость упаковки.** Устаревшая запись `license` в `pyproject.toml`
   заменена на SPDX-строку; editable-установка проходит без предупреждения о
   лицензии.

## 9. Известные ограничения

- Нет локально доступного Python 3.11: проверка выполнена на Python 3.14.10.
  CI на 3.11 подготовлен, но не запускался.
- GitHub Actions не запускался: проект не публиковался и `git push` не
  выполнялся. YAML-файл CI разобран парсером YAML; фактический прогон job —
  ручной шаг после публикации.
- Поддерживается только `.xlsx`; `.xls`, `.xlsb` и макросы не читаются.
- Читается только активный лист книги Excel.
- Схема фиксированная; лишние именованные столбцы игнорируются.
- Даты: только `YYYY-MM-DD`, `DD.MM.YYYY` и настоящие даты Excel. Временные
  метки и неоднозначные форматы отклоняются.
- Формулы Excel не пересчитываются; при отсутствии кэшированного значения
  ячейка читается пустой.
- Все данные находятся в памяти; для очень больших файлов потребуется
  потоковый режим.
- Дубликаты — только точное совпадение после нормализации; нечёткое
  сопоставление не выполняется.
- Валюта одна (рубли в подписях); налоги, скидки, возвраты и мультивалютность
  вне области задачи.
- Excel хранит числа как double; расчёты выполнены в `Decimal`, но отображение
  и последующая обработка в Excel ограничены форматом Excel.
- Визуальная проверка выполнена рендерером без нативного Excel; скриншоты не
  добавлялись, чтобы не выдавать их за реальный интерфейс заказчика.
