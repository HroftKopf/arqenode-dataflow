# Arqenode DataFlow

Локальная Python-программа для автоматической обработки таблиц продаж CSV/XLSX:
проверка и очистка данных, точные денежные расчёты и готовый Excel-отчёт с
аналитикой.

Проект демонстрирует автоматизацию типовой бизнес-задачи: вместо ручной
сверки выгрузки из учётной системы пользователь получает проверенный набор
данных, список отклонённых строк с причинами и управленческую сводку.

> Это демонстрационный проект для портфолио IT-студии Arqenode. Он не
> выполнялся для реального заказчика, не содержит персональных или коммерческих
> данных и работает полностью локально.

## Какую задачу решает проект

Небольшой компании нужно ежемесячно собирать продажи из выгрузки CSV/XLSX.
В исходных данных встречаются:

- пустые строки и пропущенные обязательные значения;
- даты в разном написании и откровенно некорректные даты;
- отрицательные цены, нулевые количества и текст вместо чисел;
- лишние пробелы в названиях товаров;
- полностью повторяющиеся строки после нормализации;
- несколько товарных позиций в одном заказе.

Arqenode DataFlow проверяет каждую строку, не «додумывает» данные, сохраняет
причины отклонения, считает выручку через `Decimal` и формирует пять листов
Excel-отчёта. Корректные строки обрабатываются даже при наличии ошибок в
других строках.

## Возможности

- Чтение `.csv` и `.xlsx` без изменения исходного файла.
- CSV: UTF-8, UTF-8 с BOM и Windows-1251; разделители `,` и `;`.
- Фиксированная схема с обязательными и необязательным столбцом.
- Валидация дат, количеств, цен, обязательных полей и полностью пустых строк.
- Нормализация пробелов и поиск точных дубликатов после нормализации.
- Отдельный лист «Ошибки» с номером исходной строки, исходными значениями и
  понятной причиной.
- Денежные расчёты через `decimal.Decimal` и округление
  `ROUND_HALF_UP` до двух знаков.
- Сводка, топ-10 товаров, выручка по месяцам и график месяцев.
- Excel-оформление: фирменные цвета, закреплённые заголовки, автофильтры,
  числовые форматы, удобная ширина столбцов.
- Экспорт очищенных данных в `cleaned.csv`.
- Защита CSV/XLSX от интерпретации недоверенных текстовых значений как формул.
- Понятные ошибки CLI и коды завершения.
- Безопасная политика перезаписи: существующие результаты не заменяются без
  явного `--force`.
- Автоматические тесты, Ruff, покрытие и GitHub Actions.

Модули разделены по ответственности: чтение не занимается проверкой,
валидатор не формирует Excel, расчёты не зависят от CLI. Этого достаточно для
задачи, без лишних интерфейсов и фреймворков.

- Интернет, API-ключи, база данных и облачные сервисы не нужны.

## Запуск

```bash
python -m arqenode_dataflow \
  --input examples/sales.xlsx \
  --output output/
```

После первого запуска в `output/` появятся:

- `report.xlsx` — Excel-отчёт;
- `cleaned.csv` — очищенные записи с выручкой.

Повторный запуск в тот же каталог по умолчанию остановится, чтобы не
перезаписать результаты незаметно. Для осознанной замены:

```bash
python -m arqenode_dataflow \
  --input examples/sales.xlsx \
  --output output/ \
  --force
```

Доступен и установленный console script:

```bash
arqenode-dataflow --input examples/sales.csv --output output/
```

### Параметры CLI

| Параметр | Назначение |
|---|---|
| `--input FILE` | Исходный файл `.csv` или `.xlsx` (обязательно) |
| `--output DIR` | Каталог для `report.xlsx` и `cleaned.csv` (по умолчанию `output`) |
| `--force` | Разрешить перезапись существующих результатов |
| `--debug` | Показать traceback для диагностики |
| `--version` | Версия программы |
| `--help` | Справка |

Коды завершения:

- `0` — файл успешно обработан;
- `1` — ошибка чтения, проверки, записи или отсутствие корректных записей;
- `2` — ошибка аргументов командной строки.

Ошибки внутри таблицы не приводят к аварийному завершению: они попадают в
лист «Ошибки», а обработка корректных строк продолжается. Если корректных
записей не осталось, отчёт не формируется и CLI возвращает код `1`.

## Формат входного файла

Первая непустая строка — заголовок. Имена столбцов нечувствительны к регистру
и лишним пробелам. Обязательные столбцы:

| Столбец | Тип | Описание |
|---|---|---|
| `order_id` | строка | Идентификатор заказа |
| `date` | дата | Дата продажи |
| `product` | строка | Наименование товара |
| `quantity` | целое | Положительное количество |
| `unit_price` | число | Неотрицательная цена единицы |

Необязательный столбец:

| Столбец | Тип | Описание |
|---|---|---|
| `category` | строка | Категория товара; может отсутствовать |

Точный пример `examples/sales.csv`:

```csv
order_id,date,product,category,quantity,unit_price
ORD-1001,2024-01-10,Ноутбук Arqenode Pro 14,Электроника,1,89990.00
ORD-1001,2024-01-10,Мышь Arqenode Silent,Аксессуары,2,2490.00
ORD-1002,2024-01-22,Монитор Arqenode View 27,Электроника,1,32990.00
ORD-1003,2024-02-05,Клавиатура Arqenode Type,Аксессуары,3,4590.00
```

Каждая строка — товарная позиция. Несколько строк с одним `order_id`
нормальны и **не считаются дубликатами**. Дубликатом считается совпадение всех
значений записи после нормализации.

### Правила дат

Поддерживаются только однозначные варианты:

- `YYYY-MM-DD` — например, `2024-05-17`;
- `DD.MM.YYYY` — например, `17.05.2024`;
- настоящая дата Excel в ячейке `.xlsx`.

Значение вроде `01/02/2024` отклоняется как неоднозначное. Числовые серийные
номера дат без форматирования не угадываются. `2024-02-30` также отклоняется.

### Правила чисел

- `quantity` — положительное целое число (`1`, `2`, `10`). `0`, `-1`, `1.5`,
  `abc` отклоняются.
- `unit_price` — конечное неотрицательное число. Поддерживаются точка и
  десятичная запятая: `1990.50`, `1990,50`, `1 990,50`.
- Цена единицы округляется до двух знаков по `ROUND_HALF_UP`, затем
  вычисляется `revenue = quantity * unit_price` и также округляется до копеек.
- Итоги складываются из уже округлённых выручек строк. Для всех денежных
  операций используется `Decimal`, не `float`.

### Очистка и ошибки

- Полностью пустые строки пропускаются и учитываются в счётчике.
- Лишние пробельные последовательности в текстовых полях схлопываются.
- Строка с несколькими проблемами отклоняется один раз; все причины
  перечисляются в одной ячейке.
- Исходные значения в листе «Ошибки» не переписываются «исправленными».
- Точные дубликаты удаляются, остаётся первое вхождение; дубликат попадает в
  «Ошибки» с причиной и ссылкой на исходную строку.
- Лишние именованные столбцы вне фиксированной схемы игнорируются. Значения в
  столбцах без заголовка и лишние ячейки приводят к отклонению строки.

## Результат

### `report.xlsx`

| Лист | Содержимое |
|---|---|
| «Данные» | Очищенные записи с датой, количеством, ценой и выручкой |
| «Ошибки» | Номер исходной строки, исходные значения и причина |
| «Сводка» | Показатели обработки, продаж и топ-10 товаров |
| «Товары» | Выручка, количество и число заказов по товарам |
| «Месяцы» | Хронологическая выручка по месяцам и график |

Лист «Данные» содержит закреплённую строку заголовков, автофильтр,
форматы дат/чисел и удобную ширину столбцов. «Сводка» открывается по умолчанию.
В оформлении используется единая тёмно-зелёная палитра с янтарным акцентом.

### `cleaned.csv`

UTF-8 с BOM, разделитель `,`, поля:

```text
order_id,date,product,category,quantity,unit_price,revenue
```

Даты в ISO (`YYYY-MM-DD`), денежные значения — с двумя знаками после точки.

### Защита от формул

Текстовые значения из исходного файла не должны исполняться Excel. В
`cleaned.csv` значения, начинающиеся с `=`, `+`, `-`, `@`, табуляции или
перевода строки, получают безопасный текстовый префикс `'`. В XLSX такие
значения записываются как строковые ячейки, а не формулы. Это касается
`order_id`, `product`, `category`, исходных значений в «Ошибках» и названий
товаров в агрегатах.

## Воспроизводимость и неизменность исходника

- Генератор использует `random.Random(seed)`, поэтому демонстрационный набор
  воспроизводим.
- Расчёты не используют текущее время и случайность.
- Исходный файл открывается только для чтения; запись результатов идёт в
  отдельный каталог.
- Результаты записываются через временные файлы и `os.replace`, чтобы не
  оставлять частично записанный отдельный файл.
- Целевой файл не может совпасть с исходным даже с `--force`.
- Повторный запуск без `--force` не перезаписывает существующие результаты.

## Ограничения первой версии

- Фиксированная схема столбцов; переименование полей не настраивается.
- Читается только активный лист Excel; `.xls` и макросы не поддерживаются.
- Даты поддерживаются только в двух однозначных текстовых форматах и как
  настоящие даты Excel; временные метки и произвольные форматы отклоняются.
- Формулы Excel не вычисляются: `openpyxl` читает только закэшированные
  значения; при их отсутствии ячейка выглядит пустой.
- Лишние именованные столбцы игнорируются, а не попадают в отчёт.
- Дубликаты ищутся только как полное совпадение после нормализации; похожие, но
  различающиеся записи не объединяются.
- Один отчёт — одна валюта с подписями в рублях; налоги, скидки, возвраты и
  мультивалютность не моделируются.
- Данные читаются в память целиком. Для демонстрационных 10 000 строк этого
  достаточно; для миллионов строк потребуется потоковая обработка.
- Excel хранит числовые ячейки как числа с плавающей точкой. Расчёты и
  округление выполняются в `Decimal` до записи, но отображение в Excel всё
  равно ограничено возможностями самого Excel.
- Программа не заменяет бухгалтерскую систему и не претендует на юридическую
  точность учёта.
