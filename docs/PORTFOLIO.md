# Портфолио: Arqenode DataFlow

## Название работы

**Arqenode DataFlow — автоматическая проверка таблиц продаж и формирование
Excel-отчёта на Python.**

Тип работы: демонстрационный проект для портфолио. Он не выполнялся для
реального заказчика, не является внедрением в конкретную компанию и не
содержит коммерческих данных.

## Проблема клиента

Типовой сценарий небольшой компании:

- продажи выгружаются из учётной системы в CSV или Excel;
- перед анализом выгрузку приходится вручную чистить: искать пустые строки,
  опечатки в датах, отрицательные цены, нулевые количества и дубликаты;
- ошибки теряются или исправляются «на глаз», поэтому итоговые суммы трудно
  проверить;
- сотрудник тратит время на повторяющиеся действия и каждый раз собирает
  сводку заново;
- руководителю нужны не сырые строки, а выручка по месяцам, товарам и
  заказам.

Такую задачу можно закрыть небольшой локальной программой, без CRM,
веб-приложения и облачной инфраструктуры.

## Реализованное решение

Python-утилита с CLI:

```bash
python -m arqenode_dataflow \
  --input examples/sales_demo.csv \
  --output examples/demo_output
```

Программа:

1. читает CSV (UTF-8, UTF-8 BOM, Windows-1251; разделители `,` и `;`) или
   XLSX;
2. проверяет фиксированную схему и сообщает, каких обязательных столбцов нет;
3. валидирует даты, количества, цены и обязательные поля;
4. нормализует пробелы, находит точные дубликаты после нормализации и
   сохраняет все отклонённые строки с причинами;
5. считает выручку и итоги через `Decimal` с округлением `ROUND_HALF_UP`;
6. формирует `report.xlsx` из пяти листов и очищенный `cleaned.csv`;
7. строит график выручки по месяцам средствами `openpyxl`;
8. защищает выгрузки от исполнения недоверенных текстовых значений как формул;
9. не изменяет исходный файл и не перезаписывает результаты без `--force`.

## Практическая польза

- **Экономия времени.** Обработка 10 000 строк занимает доли секунды после
  установки зависимостей; повторяющийся ручной аудит заменяется одной командой.
- **Прозрачность.** Каждая отклонённая строка остаётся в отчёте с номером,
  исходными данными и причиной. Нет «молчаливого» удаления.
- **Проверяемость.** Денежные расчёты выполнены в `Decimal`, правило округления
  зафиксировано и указано в отчёте и документации.
- **Готовый управленческий результат.** Руководитель получает сводку, топ-10
  товаров, разбивку по месяцам и график, а не только очищенный CSV.
- **Безопасность данных.** Всё работает локально, без Интернета, API-ключей,
  базы данных и передачи файлов третьим лицам.
- **Сопровождаемость.** Код разделён по модулям, покрыт тестами, проверяется
  Ruff и готов к CI на Python 3.11.

## Используемые технологии

- Python 3.11+;
- `openpyxl` — чтение/запись XLSX, стили, автофильтры, график;
- стандартная библиотека: `csv`, `argparse`, `decimal`, `dataclasses`,
  `pathlib`, `tempfile`;
- `pytest` и `pytest-cov` — 140 тестов, покрытие 96.76%;
- `ruff` — линтинг и форматирование;
- GitHub Actions — CI на Python 3.11 с порогом покрытия 80%.

## Что показать на скриншотах

Скриншоты должны быть сделаны с реально сгенерированных файлов, без
редактирования цифр и без выдуманных диалогов.

1. **Запуск CLI.** Терминал с командой обработки
   `examples/sales_demo.csv` и фактическим выводом:
   `10000 / 9752 / 148 / 100`.
2. **Лист «Сводка».** Заголовок с фирменной тёмно-зелёной палитрой, блоки
   «Обработка данных», «Продажи» и «Топ-10 товаров по выручке»; фактические
   показатели: 4 928 заказов, 34 043 единицы, 813 622 810,99 ₽.
3. **Лист «Ошибки».** Несколько реальных строк с разными причинами:
   нераспознанная дата, нулевое количество, `abc` вместо цены, отрицательная
   цена, точный дубликат. Видны номер строки, исходные значения и причина.
4. **Лист «Месяцы».** Таблица за 12 месяцев и столбчатый график выручки.
5. **Лист «Данные».** Шапка, закрепление, автофильтр, форматы дат и денег.
6. **Код и проверки.** Дерево модулей, фрагмент валидатора с `Decimal`,
   терминал с `140 passed` и `96.76%`, а также конфигурация CI.

Готовый файл для открытия и съёмки:
[`../examples/demo_output/report.xlsx`](../examples/demo_output/report.xlsx).

Не следует выдавать скриншот за внедрение у конкретного клиента. Подпись
должна честно говорить: «демонстрационный набор, 10 000 синтетических строк».

## Что подчеркнуть в описании на Kwork

- «Не просто парсер CSV, а полный цикл: проверка → очистка → расчёт → отчёт».
- «Ошибочные строки не удаляются молча: по каждой есть причина и исходные
  значения».
- «Деньги считаются через Decimal, правило округления зафиксировано».
- «Работает локально, без подписок и облака».
- «Есть тесты, покрытие и настраиваемый CI».
- «Фиксированная схема первой версии — это осознанное ограничение, а не
  недоделка».

## Важное уточнение

Это самостоятельная демонстрационная работа для портфолио. Формулировки
«разработано для компании», «внедрено у клиента» или «сэкономило клиенту N
рублей» использовать нельзя: реального заказчика и подтверждённых бизнес-метрик
нет. Корректная формулировка — «демонстрационный проект, показывающий подход к
автоматизации обработки таблиц».
